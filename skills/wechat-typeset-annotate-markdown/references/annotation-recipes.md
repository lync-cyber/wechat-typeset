# 段落标注配方（独家 reference）

> 10 个典型段落 → 推荐容器的对照表。给 LLM 在标注阶段做"段落分类 → 容器提议"的决策依据。

## 配方 1：开篇总览（intro / abstract）

**段落特征**：

- 文章开头 2-4 行
- 概括"本文要讲什么"
- 不含具体论点和数据

**信号词**：本文 / 简言之 / 先说结论 / 一句话总结 / TL;DR / "我们将在本文..."

**容器决策**：

- 通用主题（default / tech-* / life-*）：**`::: intro`**
- 深度刊主题（business-finance / industry-observer / academic-frontier）：**`::: abstract`**（更克制，无装饰底）

**例子**：

```markdown
# RSA 算法在量子计算时代的失效路径

::: intro
本文从公钥密码学的数学基础出发，回顾 Shor 算法对大数分解的多项式时间加速，
并给出 NIST 后量子标准化的当前进度与三类主流方案的工程权衡。
:::

## 第一节 ...
```

## 配方 2：金句卡（quote-card）

**段落特征**：

- 整段是一句话或两句话
- 句末标点完整（不是断章式提取）
- 长度 ≤2 行（更长走 highlight / blockquote）
- 经常配有"——作者"或文末归属

**容器决策**：`::: quote-card`（不加 variant，走 persona 默认；想强出位用 `variant=magazine-dropcap`）

**例子**：

原文：
```markdown
> 预览好看、粘贴后塌——这种情况在 wechat-typeset 里是 bug，不是特性。
```

改为：
```markdown
::: quote-card
预览好看、粘贴后塌——这种情况在 wechat-typeset 里是 bug，不是特性。
:::
```

**坑**：原 markdown blockquote (`>`) 是长引用（多段、可含列表），quote-card 是**单句金句**。不要把多段长引用塞进 quote-card，那是 highlight 或 blockquote 的位置。

---

## 配方 3：高亮重点段（highlight）

**段落特征**：

- 一整段（3-6 行）
- 全文的"核心论点 / 中心句"，读者快速浏览时不可错过
- 不是金句（没有提取式的修辞）

**容器决策**：`::: highlight`

**例子**：

```markdown
::: highlight
RSA-2048 在 100 万逻辑量子比特的容错量子计算机上分解需要 ≈ 8 小时——
这是 IBM 2024 路线图给出的下界。当前我们离这台机器有 4-6 个量级的工程差距，
但这种差距正在以指数级缩短。
:::
```

---

## 配方 4：步骤卡（steps）

**段落特征**：

- 有序列表（`1.` / `2.` / `3.` ...）
- 至少 3 条
- 每条以**动词开头**（"打开" / "切换到" / "运行" / "复制"）
- 整体描述"操作流程"而非"枚举要点"

**容器决策**：`::: steps`（包外即可，内部保留 1./2./3.）

**例子**：

原文：
```markdown
1. 打开公众号编辑器
2. 切换到草稿箱
3. 点击粘贴按钮
4. 检查样式是否对齐
```

改为：
```markdown
::: steps
1. 打开公众号编辑器
2. 切换到草稿箱
3. 点击粘贴按钮
4. 检查样式是否对齐
:::
```

**坑**：纯"要点列表"（- 项 1 / - 项 2 / - 项 3）**不要**包 steps——steps 的视觉骨架（number-circle / timeline-dot）只在"步骤"语义下成立。

## 配方 5：双列对比（compare）

**段落特征**：

- 文中出现"优点 / 缺点"、"前 / 后"、"A 派 / B 派"明确对比结构
- 两列内容长度近似

**容器决策**：`:::: compare`（外 4 内 3）

**例子**：

原文：
```markdown
**优点**：无需登录、本地草稿不丢、375 px 预览。
**缺点**：仅适配公众号、依赖剪贴板权限。
```

改为：
```markdown
:::: compare
::: pros 优点
- 无需登录，草稿在本地
- 375 px 预览锁死不变形
:::
::: cons 缺点
- 仅适配微信公众号
- 需要浏览器剪贴板权限
:::
::::
```

**坑**：单边长（一列 5 条 vs 另一列 1 条）视觉失衡，不要硬包；改用 highlight + 普通列表。

## 配方 6：提示 / 警告（admonition 5 态）

**段落特征**：

- 整段是"对读者说的话"——补充、提醒、警告
- 区分 5 态语义

**容器决策**：

| 段落语义 | 容器 |
| --- | --- |
| 正向小贴士 | `::: tip` |
| 需读者留意（不致命） | `::: warning` |
| 中性说明 / 补充 | `::: info` |
| 高风险 / 错误示范 | `::: danger` |
| 中性补注 / 参考资料 / 不抢色 | `::: note` |

**信号词**：

- tip：💡 / "顺便" / "小贴士" / "建议"
- warning：⚠️ / "注意" / "需要留意"
- info：ℹ️ / "补充说明" / "补充一句"
- danger：❌ / "切忌" / "千万不要" / 危险命令 `rm -rf`
- note：📝 / "注：" / "[1]" / "参考"

**例子**：

```markdown
::: warning 注意 Windows 路径
本文示例假设 Unix path 分隔符。Windows 上请把 `/` 替换成 `\`，
PowerShell 中 quotes 行为也不同。
:::
```

## 配方 7：数据卡（key-number）

**段落特征**：

- 一个核心数字 + 一句标签 + 一段说明
- 数字本体显眼到值得专门卡片化

**容器决策**：`::: key-number value=<数字> <标签短语>`

**例子**：

```markdown
::: key-number value=87% 留存率
新用户 7 日留存——比行业基准 31% 高 56 个百分点。
口碑分享与产品病毒系数的乘积驱动。
:::
```

**坑**：value 是 attr，不是正文；正文写说明，不要重复数字。

---

## 配方 8：章节大标题（section-title）

**段落特征**：

- 文章有明显多节结构（≥3 节）
- 每节起始的 H2 想要更强的视觉分割

**容器决策**：H2 升级为 `::: section-title`（保留 ## 一并写也可，section-title 自身就是块级标题；推荐 H2 + section-title 二选一）

**例子**：

原文：
```markdown
## 第一节 · 数学基础
```

改为：
```markdown
::: section-title
第一节 · 数学基础
:::
```

**坑**：不要每个 H2 都升级——一篇文章 3-5 个 section-title 即可；过密视觉吵闹。

---

## 配方 9：文末 CTA（footer-cta）

**段落特征**：

- 出现在文末
- "关注我 / 点赞 / 转发 / 扫码加群" 等引导文案
- 经常带着二维码图

**容器决策**：

```markdown
::: footer-cta 觉得有用？ cta=关注我 href=https://mp.weixin.qq.com/s/xxx
一句引导文案，正文里继续写
:::
```

**搭配**：上方可加 `::: qrcode`，下方可加 `::: recommend` 列推荐阅读，组成"收束三件套"。

---

## 配方 10：参考阅读（see-also / recommend）

**段落特征**：

- 文末"延伸阅读"、"参考资料"、"相关文章"
- 是链接列表

**容器决策**：

- 学术 / 教程类（academic-frontier / tech-explainer）：`::: see-also`
- 普通文章：`::: recommend`

**例子**：

```markdown
::: see-also 延伸阅读
- [NIST 后量子密码学项目](https://csrc.nist.gov/projects/post-quantum-cryptography)
- [Shor's Algorithm in Wikipedia](https://en.wikipedia.org/wiki/Shor%27s_algorithm)
:::
```

## 不要标注的情况

下列段落保留原 markdown，**不**包容器：

- 简单陈述句（每段都包 → 视觉地板砖效果）
- 常规无序列表（要点枚举）
- 代码块（除非主题是 tech-explainer 且想给加 codeBlock variant=header-bar——但这是主题层面决定，不是标注层面）
- 表格（GFM 表格直接可渲，不需要容器包裹）
- 普通超链接段落

## 节奏建议

- **一篇 1500-3000 字的文章**：3-6 个内容容器是健康量
- **一篇 ≥5000 字的深度文**：6-10 个容器，且至少 1 个 abstract + 1 个 footer-cta + 2-3 个 section-title
- **一篇 ≤800 字的短文**：1-3 个容器，可能只有 quote-card 或 footer-cta 即可

**红灯**：连续 3 个段落都被包成容器 → 视觉密度过高，去掉中间那个。
