# 段落标注配方

这些配方是按需使用的格式示例，不是段落分类后必须套用的规则。普通 Markdown 可以直接渲染；保留全文不加组件也是有效结果。

先确认原文是否已有明确语义，以及组件是否能解决具体阅读需求。没有明确收益时保留原样。用户明确指定格式时可使用对应组件，但不要为了适配容器重写正文、补写内容或调整内容顺序；保留事实、数字、限定词、引文全文和署名。以下示例仅演示已有内容的包裹方式，不作为新文章的文案来源。

## 配方 1：已有导语或摘要（intro / abstract）

开头已有独立总览，且需要单独呈现时，可用 `intro`；原文已有摘要时，可用 `abstract`。开头位置、信号词或主题本身都不足以决定添加组件，不要为深度文章另写摘要。

例如，原文已有下面这段导语时，可原样包裹：

```markdown
::: intro
本文记录一次公众号草稿排版过程，说明预览与粘贴后的检查方法。
:::
```

已有摘要同样可以使用：

```markdown
::: abstract 摘要
本文记录一次公众号草稿排版过程，说明预览与粘贴后的检查方法。
:::
```

两者按原文语义和用户需求选择，不重复加入。

## 配方 2：明确需要的短引文卡（quote-card）

普通引用默认保留 Markdown `>`。句子短、有署名或措辞醒目，都不意味着它必须成为“金句”。只有原文已有独立短引文且确需卡片呈现，或用户指定时，才使用 `quote-card`。不要抽取半句、删除上下文限定或丢掉署名。

原文：

```markdown
> 在这次测试中，预览结果与粘贴后的结果一致。
>
> ——测试记录
```

需要卡片时：

```markdown
::: quote-card
在这次测试中，预览结果与粘贴后的结果一致。

——测试记录
:::
```

多段长引用或含列表的引用继续保留 `>`；不要为了卡片缩写引文，也不因长度改成 `highlight`。

## 配方 3：明确需要突出的一段（highlight）

原文已有独立重点段，且确需整段突出时，可用 `highlight`。保留整段文字，包括适用范围和不确定性；不要把普通陈述改写成更强的结论。

```markdown
::: highlight
本次检查只覆盖桌面端预览和公众号草稿。移动端的显示效果尚未验证。
:::
```

## 配方 4：已有操作流程（steps）

有序列表确实表达先后操作，且需要步骤卡时，可以外包 `steps`。保留原有步骤数量、文字和顺序，不补足条目、不改成动词句来适配容器。要点枚举继续使用普通列表。

原文：

```markdown
1. 打开公众号编辑器
2. 切换到草稿箱
3. 检查草稿内容
```

需要步骤卡时：

```markdown
::: steps
1. 打开公众号编辑器
2. 切换到草稿箱
3. 检查草稿内容
:::
```

## 配方 5：已有双侧对比（compare）

原文已有清楚的双侧对比，且适合并排阅读时，可用 `:::: compare`（外 4 内 3）。不要为了列宽或条目数对称而增删、改写事实。

原文：

```markdown
**优点**：无需登录、本地草稿不丢、375 px 预览。

**缺点**：仅适配公众号、依赖剪贴板权限。
```

需要对比卡时，仅把已有标签放入容器标题，正文措辞不变：

```markdown
:::: compare
::: pros 优点
无需登录、本地草稿不丢、375 px 预览。
:::
::: cons 缺点
仅适配公众号、依赖剪贴板权限。
:::
::::
```

两侧长度悬殊或不适合并排时，保留原文结构即可，不必换成其他组件。

## 配方 6：已有提示或警告（admonition 5 态）

原文已有补充、提醒或警告，需要与正文区分时，按真实语义选择。单个“建议”“注意”或表情不是自动包裹的依据，不升级原文的风险程度。

| 原文语义 | 可选容器 |
| --- | --- |
| 正向小贴士 | `::: tip` |
| 需要留意的事项 | `::: warning` |
| 中性说明或补充 | `::: info` |
| 明确的危险或错误示范 | `::: danger` |
| 中性补注或参考资料 | `::: note` |

```markdown
::: warning
粘贴后请检查图片和链接是否完整。
:::
```

原文没有独立标题时，无需新写容器标题。

## 配方 7：已有独立指标（key-number）

正文提到数字、比例或年份时，默认保留正文。只有原文已有独立指标及其标签、口径，且确需突出或用户指定数据卡时，才考虑 `::: key-number value=<数字> <标签短语>`。

例如，原文已经独立列出该指标：

```markdown
**7 日留存率：87%**

统计范围为本次测试的 100 名新用户，仅供内部观察。
```

需要数据卡时：

```markdown
::: key-number value=87% 7 日留存率
统计范围为本次测试的 100 名新用户，仅供内部观察。
:::
```

`value` 是属性，会呈现为卡片数值；保留指标的单位、时间范围、样本范围和限定词。若拆分会使“约”“最高”“可能”等限定词与数字脱离，保留原文结构。不要推算新指标、添加比较基准或为了避免重复删改原有说明。

## 配方 8：已有章节标题（section-title）

普通 H2 可以直接渲染。只有确需更强的视觉分隔或用户指定时，才把已有标题改为 `section-title`。保留标题文字和层次，不因章节数量而批量升级，也不新编章节编号。

原文：

```markdown
## 第一节 · 数学基础
```

需要章节组件时：

```markdown
::: section-title
第一节 · 数学基础
:::
```

同一个标题无需再重复输出一份 H2。

## 配方 9：已有文末引导（footer-cta）

原文已有关注、点赞、转发等引导，且需要组件格式时，可用 `footer-cta`。不要为文章补写 CTA，也不要自动搭配二维码或推荐阅读。按钮文案和链接必须来自原文或用户提供的信息。

以下仅演示用户已提供标题、引导文案、按钮文字和目标链接时的语法：

```markdown
::: footer-cta 继续阅读 cta=查看相关文章 href=https://example.com/articles
相关文章见下方链接。
:::
```

缺少这些材料时，保留已有文末文字或链接，不用示例地址补齐。

## 配方 10：已有参考阅读（recommend）

文末已有参考资料或相关文章列表，需要独立呈现时，可以使用 `recommend variant=academic-refs`（参考引用）或 `recommend variant=card-list`（延伸阅读）。依据原有列表用途选择，不按主题自动补推荐链接；保留链接标题、URL 和原有顺序。

```markdown
::: recommend variant=academic-refs 延伸阅读
- [Markdown Guide](https://www.markdownguide.org/)
- [CommonMark](https://commonmark.org/)
:::
```

## 保留原样与整体检查

- 普通段落、标题、引用、列表、代码块、GFM 表格和链接均可直接渲染，无需容器。
- 不设组件最低数量，不按字数或主题配额标注；零组件也可以交付。
- 检查每个新增组件是否有明确用途。连续多个组件时检查是否过密，按语义决定保留或撤回，不机械删除固定位置的组件。
- 最后对照原文核验文字、数字、限定词、引文署名和顺序；不要以“优化节奏”为由改写或搬移内容。
