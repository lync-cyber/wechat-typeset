# 行内扩展判定规则

5 种行内扩展的语义边界与组合说明。默认保留原文；零行内标注是完整有效的结果。先沿用已有的粗体、斜体、行内代码等 Markdown 表达，不因出现新概念、专有名词或主题偏好自动增加强调。

仅在原文已有明确强调需求或用户指定格式时添加标记。保留被标注文字及其上下文，不改写事实、数字、限定词或引文，不为填满“强调名额”新增标记。

## 总览

| 语法 | 视觉 | 语义 |
| --- | --- | --- |
| `==高亮==` | 荧光笔背景色 | 关键词强调 |
| `[.着重.]` | 字下圆点 | 中文传统着重 |
| `[~波浪~]` | 波浪下划线 | 警示性或疑问性强调 |
| `~~删除~~` | 删除线 | 原值已弃或修改痕迹 |
| `++插入++` | 下划线 | 新增或强调“加入”动作 |

## 各扩展用法

以下例子演示语法；不是要求遇到类似内容就添加标记。

### `==高亮==` · 荧光笔

适合确需让扫读者注意的关键词或短语。选取表达完整语义的最短范围，不按固定字符数切断术语或限定词，也不扩大到整段。已有粗体足以表达重点时，通常保留粗体即可。

```markdown
这一步只影响 ==当前草稿==。
```

### `[.着重.]` · 中文着重号

适合中文短语的语义强调。原文已有清楚的强调时无须再叠加。

```markdown
修改前请先 [.保留原稿.]。
```

`==` 与 `[.着重.]` 都是可选形式；依据已有表达和用户偏好选择。新增标记尽量保持一致，不为了统一风格清除原文已有的不同标记。

### `[~波浪~]` · 警示性强调

适合原文已表达疑问、限制或需要留意的短语。标注不能凭空添加风险或不确定性。

```markdown
工程实践中，[~异步并不一定更快~]——任务规模小时同步反而更快。
```

### `~~删除~~` · 删除线

用于原文已有或用户明确要求展示的废弃值、修订痕迹、自嘲表达。普通排版不替作者判定某段内容已经失效。

```markdown
原定 ~~周一~~，现改为周三。
```

### `++插入++` · 下划线 ins

用于原文已有或用户指定的新增内容标记，可与 `~~删除~~` 配对展示修订。不要把普通强调自动解释为新增，也不要把真实的新增标记替换成高亮。

```markdown
原定 ~~周一~~，现改为 ++周三++。
```

## 密度与保留原样

- 没有必须标注的词，也没有按字数计算的最低数量。已有表达清楚时不添加。
- 通常一段只新增一个强调焦点；删除与插入配对属于同一次修订表达，不机械拆开。
- 多个相邻标记或整段强调时，检查每处是否必要。可以撤回本次新增的冗余标记，不自动删除作者已有强调。
- 避免为了减少标记而改写正文，或把整段行内强调自动转换为 `highlight` 容器。

例如，下面的新增高亮分散了注意力：

```markdown
这一步 ==只== 影响 ==当前== ==草稿==。
```

确有强调范围的需要时，可以只标完整短语：

```markdown
这一步只影响 ==当前草稿==。
```

没有明确强调需求时，保持普通正文也完全有效。

## 组合规则

优先保留一种已有强调；不要主动把粗体、斜体与高亮或着重号叠加。现有语法支持组合不等于推荐新增组合。用户明确要求组合形式时，按现有渲染能力处理并检查效果，不改扩展语法。

互不重叠、语义不同的标记可以共存：

```markdown
[.关键.]参数是 `mode`。
~~原值~~ → ++新值++
```

避免新增这类叠加：

- `**==重点==**` / `*==重点==*`：原有粗体或斜体通常已经足够。
- `**[.重复.]**`：重复表达强调。
- `==[~混合~]==`：叠加两种扩展，公众号渲染可能不稳定。

## 主题偏好

主题可以帮助选择需要新增的标记样式，但不决定哪些文字必须强调。教程中可选 `==高亮==`，中文严肃文体中可选 `[.着重.]`；工程文章已有行内代码时常无需额外标记。优先尊重原文表达和用户指定格式，不按 persona 配额或强制混搭。

## 语法边界

- 不给整段新增行内扩展；先判断是否需要强调，不能据此自动补一个块级组件。
- 不在 `::: free` 之外引入 HTML 行内标签（如 `<u>` / `<mark>`）；这些不是此处约定的行内扩展。
- 标题本身已有视觉层次，默认不再新增行内扩展。
- 不在 `:::` 容器的 open 行（title 段）使用行内扩展；`::: tip ==重要==` 会把 `==` 当字面量传给 renderer。
