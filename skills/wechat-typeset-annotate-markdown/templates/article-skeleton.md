# 文章骨架模板

普通 Markdown 可以直接渲染；零组件、零行内扩展也是完整有效的文章。已有文章沿用原有结构，不必套用骨架。新建文档时可从下面的最小示意起步，仅保留实际需要的标题与正文。

```markdown
# {原文标题}

{原文正文}

## {原文已有的小标题，如有}

{后续原文正文}
```

## 按需加入组件

组件只服务于原文已有的明确语义或用户指定的格式。不要按字数、主题或模板位置凑组件，也不要为使用组件新写摘要、金句、数据说明、CTA、参考资料或署名。

- 普通标题、段落、引用、列表、代码和表格可保持原样。
- 已有完整的导语或摘要，需要单独呈现时，才考虑 `intro` 或 `abstract`。
- 引用默认保留 `>`；只有明确需要短引文卡片时才考虑 `quote-card`，保留引文全文和署名。
- 正文提到数字不自动转为 `key-number`；原文已有独立指标，且需要突出时才考虑数据卡。
- 用户明确要求组件格式时可使用；仍保留原文事实、数字、限定词、引文署名和内容顺序，不补造缺失材料。

只复制本次确实需要的示例。更多按语义选择的例子见 [annotation-recipes.md](../references/annotation-recipes.md)。

已有操作流程需要步骤卡时，包裹原列表：

```markdown
::: steps
1. 打开公众号编辑器
2. 切换到草稿箱
3. 检查草稿内容
:::
```

已有注意事项需要单独呈现时，保留原句：

```markdown
::: warning
粘贴后请检查图片和链接是否完整。
:::
```

## variant 与其他扩展

默认不添加 `variant=xxx`；主题默认样式不适合本段或用户指定样式时，再按支持的变体覆盖。例如，明确需要 § 装饰分隔时可使用：

```markdown
::: divider variant=glyph glyph=§
:::
```

- 不预置 `::: free`；确有无法归类的编辑部补注等内容时再考虑。
- 不预置 `::: mpvoice` / `::: mpvideo` 占位卡；用户明确需要公众号后台语音或视频时再处理。
- 只使用词汇表已有的 fence 名，不添加 `::: insight` / `::: callout` 等未定义语法。
